# Charts research workspace

The Charts page now uses the existing TheOnePercent database history through the signed-in `Cloud.client`. It calls the existing security-invoker `history_catalog`, `history_months`, and `history_read_payload` RPCs. No database schema, grants, account assignments, uploads or publication flags are changed. No privileged key or archive payload is packaged with the site.

`charts-history.js` chooses the native M1, H1 or D1 archive for the requested interval. Larger intervals aggregate actual OHLC candles on UTC boundaries (weeks start Monday; months follow calendar boundaries). Smaller candles are never inferred from larger bars. The adapter loads a bounded recent window of up to 620 plotted bars from at most 12 monthly chunks. It verifies compressed size, SHA-256, payload identity, UTC dates, candle count, strict timestamp ordering, OHLC invariants and coverage before returning data. The first aggregation bucket is omitted where it may lack leading context. Archive gaps remain gaps; the latest bucket may be incomplete.

Charts defaults to database mode even if an older device preference enabled demo mode. There are no external market API or Binance stream calls in database mode. Sign-in, assignment, unsupported intervals and read errors leave a labelled empty state. An explicit optional demo toggle remains under Workspace for exploring tools; it is labelled synthetic and resets to database mode on the next Charts load. Stored history is never tick-mutated.

Archives contain bid OHLC without volume. Volume studies and profile rendering are unavailable in database mode. Existing position-sizing assumptions remain local instrument metadata; archive candles are not executable quotes. Source and last stored candle date appear in the footer; dates can vary by provider and base timeframe. Instrument details use the correct millisecond candle timestamp.

The compact toolbar, local brand mark, drawing favourites, floating edit bar, vector Object Tree controls and settings categories reuse the existing engine, tool IDs, account storage and workspace save flow. Drawing changes support the existing undo/redo history. Favourites reuse `chartsFavTools`; no existing storage key is renamed. The profile uses the actual signed-in account image where available and an account icon otherwise.
